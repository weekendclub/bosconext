# BOSCO NEXT 公式サイト

東京を拠点に活動するソーシャルフットボールクラブ **BOSCO NEXT（ボスコ ネクスト）** の公式サイトです。

| | URL |
|---|---|
| 公開サイト（正規URL） | https://weekendclub.github.io/bosconext/ |
| 編集画面（CMS） | https://bosconext.netlify.app/admin/ |
| ミラー（ログイン用） | https://bosconext.netlify.app/ |

> `https://weekendclub.github.io/bosconext/admin/` を開いた場合も、自動で Netlify 側の編集画面へ転送されます。

---

## 更新のしかた

**ふだんの更新は、ほぼすべて編集画面（`/admin`）のフォームでできます。** HTML や GitHub を触る必要はありません。

くわしくは **[編集ガイド.md](編集ガイド.md)** を読んでください。初回だけ必要なログイン設定（GitHub の OAuth アプリ作成 → Netlify に登録）も、そこに手順があります。

編集画面から編集できるもの：お知らせ／トップの文章・写真／チーム・選手／スケジュール／大会戦績／フォトギャラリー／リンク

├── images/
│   ├── emblem.png        クラブエンブレム（いただいた元データ・赤背景）

├── config.yml            編集画面の設定（項目・保存先）
│
├── backend/
│   └── contact-form.gs   お問い合わせフォームの受け口（Google Apps Script に貼って使う）
│
├── favicon-32.png        タブのアイコン（クラブエンブレム・背景透過）
├── favicon-192.png       同上・高解像度の画面向け
├── apple-touch-icon.png  iPhone のホーム画面に追加したときのアイコン（赤地）
│
├── sitemap.xml           検索エンジン向けサイトマップ

- ページの中身（お知らせ・選手・戦績など）は `*.json` に入っていて、各ページが読み込んで表示します。
- デザインを直したいときは `style.css`、メニューや SNS リンクは `site.js` の `SITE_INFO` を編集します。

## お問い合わせフォームの仕組み

お問い合わせページ（`contact.html`）は、**ご用件を選ぶと、その用件に必要な入力欄だけが出る**フォームです。
必須の項目が空のままでは送れないので、内容の足りないお問い合わせが届きにくくなります。

| ご用件 | 入力する項目（★＝必須） | 届け先 |
|---|---|---|
| 入部・体験・見学 | お名前★／フリガナ★／性別★／メール★／メール（もう1つ）／障がいの有無★／メッセージ★ | 運営（…-management） |
| マネージャー・スタッフ希望 | お名前★／フリガナ★／性別★／メール★／メール（もう1つ）／メッセージ★ | 運営（…-management） |
| 練習試合・対戦のご相談 | チーム名★／ご担当者のお名前★／メール★／メール（もう1つ）／メッセージ★ | 対戦（…-matchmake） |
| その他のお問い合わせ | お名前★／メール★／メール（もう1つ）／メッセージ★ | 代表（bosco_futsal） |

ほかのページの「体験・入部」ボタンは入部用（`contact.html?type=join`）、トップの「対戦求む」は対戦用（`contact.html?type=match`）の入力欄が選ばれた状態で開きます。

### 送信のしくみ（2通り）

`contact.html` の下のほうにある `CONTACT` の **`endpoint`（受け口のURL）** で切り替わります。

- **URL が入っているとき** … 「送信する」を押すと、その場で送信されます（メールアプリは開きません）。
  内容は `backend/contact-form.gs`（Google Apps Script）が受け取り、ご用件に応じた担当のアドレスへメールで届けます。
  届いたメールにそのまま「返信」すると、問い合わせた本人に届きます。
- **空（`""`）のとき** … 同じ入力チェックを通したうえで、入力内容が入ったメールを、送る人のメールアプリで開きます。
  受け口を用意するまでのつなぎです。

うまく送信できなかったとき（通信の不調など）は、入力内容を消さずに「もう一度送信する／メールアプリで送る／内容をコピーする」の案内が出ます。

### 受け口を用意する（最初の1回だけ・5分ほど）

Google アカウントが1つ必要です。チーム共用の Google アカウントがあればそれを、なければ管理する人のアカウントを使います。

1. そのアカウントでログインした状態で <https://script.new> を開く
2. 最初から入っている文字（`function myFunction() { }`）を全部消し、[`backend/contact-form.gs`](backend/contact-form.gs) の中身を全部コピーして貼り付ける → 保存ボタン（💾）を押す
3. 右上の **「デプロイ」→「新しいデプロイ」** → 「種類の選択」の歯車（⚙）→ **「ウェブアプリ」** を選び、次のようにして **「デプロイ」**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. **「アクセスを承認」** → アカウントを選ぶ → 「このアプリは Google で確認されていません」と出たら **「詳細」→「（プロジェクト名）（安全ではないページ）に移動」→「許可」**
   （自分で作ったスクリプトには必ず出る表示です。許可する内容は「メールの送信」だけです）
5. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/……/exec`）をコピーする
6. `contact.html` の `endpoint: ""` の `""` の中に、その URL を貼り付けて保存する

> 画面の文言は、Google 側の変更で少し変わることがあります。

設置できたら、実際にフォームから1通送って、担当のアドレスに届くか確かめてください。
**最初のうちは迷惑メールフォルダに入ることがあります。** その場合は「迷惑メールではない」にしておくと、次から受信箱に届きやすくなります。

### 知っておくこと

- 届くメールの「差出人」は、受け口を置いた Google アカウントの Gmail アドレスになります（チームの受信箱にだけ見えます。問い合わせた人には見えません）。
- 受け口にできるのは「あらかじめ決めた担当アドレスにメールを送ること」だけです。ほかの宛先には送れません。
- 受け付けは **1日40通まで**です（いたずらや機械による大量送信への備え）。上限に達したあとは、フォームに「メールアプリ・SNSでご連絡ください」という案内が出ます。
  数は `contact-form.gs` の `dailyLimit` で変えられます（Google 側の上限は、無料の Gmail アカウントで1日100通）。
- 問い合わせた人への自動返信メールは送りません（他人のアドレスを入れて悪用されるのを防ぐため）。送信後は完了ページ（`thanks.html`）を表示します。
- フォームには**障がいに関する情報**が入ります。メールを受け取るアカウントと、受け口を置いた Google アカウントは、2段階認証をかけ、見られる人を必要な範囲に絞ってください。
  送ったメールの控えが Google アカウント側（Gmail の「送信済み」）に残る場合があります。残っていて不要なら、消してかまいません。

### 項目や届け先を変えるとき

| 変えたいこと | 直す場所 |
|---|---|
| 入力欄の見出し・例文・案内文 | `contact.html`（入力欄の HTML／`CONTACT.types`） |
| 届け先のアドレス | `backend/contact-form.gs` の `CONFIG.recipients` と、`contact.html` の `CONTACT.mailTo`（**両方**） |
| 項目を増やす・必須を変える | `contact.html`（入力欄の HTML と、`ORDER`・`LABEL`・`OPTIONAL`）と、`backend/contact-form.gs`（`TYPES`・`LABELS`・`LIMITS`）の**両方** |

`contact-form.gs` を直したときは、Apps Script の画面にも同じ内容を貼り直し、
**「デプロイ」→「デプロイを管理」→ 鉛筆（編集）→ バージョン「新バージョン」→「デプロイ」** で反映します。
「新しいデプロイ」を作り直すと URL が変わってしまうので、必ず「デプロイを管理」から行ってください。

## 手元で確認する（任意）

JSON はブラウザで直接ファイルを開くと読み込めません（`file://` では `fetch` がブロックされます）。
確認するときは簡易サーバを立ててください。

```bash
python3 -m http.server 8000
# → http://localhost:8000/        で表示を確認
# → http://localhost:8000/admin/  で編集画面を確認（ローカルではログインは不要・不可）
```

## 公開の仕組み

- `main` ブランチに push すると、**GitHub Pages**（このリポジトリ / root）と **Netlify**（`bosconext` プロジェクト）の両方に自動で反映されます。
- 画像などのパスは**相対パス**で書いています。GitHub Pages（`/bosconext/` の下）と Netlify（ルート直下）のどちらでも同じように解決させるためです。ルートからの絶対パス（`/images/...`）は使わないでください。
- ファビコンも各ページの `<head>` から相対パスで指定しています。指定を消すと、ブラウザは**ドメイン直下**の `/favicon.ico` を探しにいって 404 になります（GitHub Pages ではそこはこのリポジトリの管理外です）。ファイルを置くだけでは足りないので、`<link rel="icon">` は消さないでください。
- 各ページの `canonical` は GitHub Pages 側を指しています（検索結果に出したい正規URL）。
